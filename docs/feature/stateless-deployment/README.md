# 无状态应用部署

## 目标

应用容器不需要持久化数据卷。已接受的录音、转写和人物资料保存在 PostgreSQL，应用实例可重建或替换。

## 行为

- 原始音频、播放副本、业务元数据、会话和任务均持久化到 PostgreSQL。
- 运行时临时磁盘只用于探测、转码和临时缓存；删除整个临时目录不丢失已接受的数据。
- 允许多个 Go 实例连接同一数据库；请求无需粘性会话，后台任务通过数据库租约协调。
- 上传收到成功响应后可从另一实例访问；响应前中断允许重传，不承诺无感迁移正在上传的连接。
- 任务接管从数据库恢复；无法确定远端是否受理的操作保持待核对，不盲目重新收费。
- 备份数据只需 PostgreSQL；部署配置与秘密单独由运营者保管。恢复时停止旧实例，隔离可能重试的转写任务；核对后启用新任务，旧隔离不能自动清除。

## 验收

两个应用实例共享真实 PostgreSQL。A 上传成功后销毁 A 及其临时目录，B 可播放、编辑和继续后台任务。
会话、导入选项和任务状态保留；并发领取不重复执行已知远端创建操作。
