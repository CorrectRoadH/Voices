# 查看与检查更新

## 用户目标与起始状态

管理员已登录，希望知道实例是否有新的正式版本和有效公告；更新服务只通知，不自动安装软件。

## 完整路径

1. 进入服务器设置，查看当前构建版本和更新服务状态。 {#open}
2. 服务启用时点击手动检查，检查成功显示最新稳定版本、发布说明、发布时间及有效公告。更新服务不可用或暂无正式版本时显示检查失败，保留此前成功的版本信息及最后成功时间，不显示已是当前发布版本。禁用时检查按钮不可用；开发版不显示已是当前发布版本。 {#read}
3. 点击“版本更新日志”或“查看公告详情”打开 Dialog 阅读完整 Markdown；标题、列表、强调、代码与表格正确呈现，长内容在弹窗内部滚动，关闭后焦点回到入口。页面保留公告标题、严重级别与摘要，最近检查和最后成功时间相同时只显示一次；只有最新正式版本高于当前正式版本才提示升级。更新提示不自动安装软件，部署步骤见运行文档。 {#read-notices}

## 结果与异常

普通用户不能访问更新接口；手动检查复用管理员、CSRF、来源与恢复模式约束。远端内容不执行 HTML，链接只允许不含凭据的 HTTPS 地址。上游请求最多 5 秒，检查间隔至少 60 秒，并发检查合并；后台启动和每日检查随应用取消而退出。

验收覆盖成功、失败、首次未知、禁用、版本比较、缓存过期公告、权限拒绝、请求取消和移动端布局。发布说明唯一来源为 GitHub Releases，公告独立随 Worker 部署更新。

部署者可设置 UPDATE_TELEMETRY=true；默认开启（UPDATE_TELEMETRY=false 可关闭），恢复模式禁发。启用后实际检查向 UPDATE_URL 发送随机安装 ID、版本、Go版本、OS、架构；不发送业务内容。数据库克隆为独立部署时须重新生成安装 ID，不改变任务租约身份。统计失败不影响更新，身份读取失败或缺失时仅禁用统计。验收覆盖关闭/开启/恢复模式、身份稳定与失败降级，详见 [统计方案](../architecture/telemetry.md)。
