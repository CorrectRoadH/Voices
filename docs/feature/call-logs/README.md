# 统一外部调用记录

## 目标

个人与管理员能查到启用记录后的转写及 AI 请求尝试，包括成功、失败、结果不明和中断，而不必从当前任务状态猜测历史。个人与管理端读取同一份持久化记录，权限决定可见范围。

## 行为与边界

- 任务代表处理目标；调用代表执行一次服务商操作的尝试。一个任务可包含上传、提交、轮询、读取结果和清理等多次调用。调用成功不等于整个转写任务完成。
- STT 覆盖 upload、submit、poll、fetch_result、delete_file、delete_transcription。AI 覆盖 generate_insights、list_models、test_model。本地预处理、应用 API 请求与版本检查不计入外部 AI/STT 调用。
- 每次尝试保存时间、耗时、类型、操作、服务商、模型、状态、受控错误原因、已知 HTTP 状态及关联 ID。STT 保存音频时长；AI 用量只有服务商确实返回才显示，缺失显示未知，不能写成零或估算账单。
- 管理端可按账号、类型、操作、服务商、模型、状态、时间及关联 ID 筛选全站记录。个人仅能读取本人记录；管理员跨用户只读取运维元数据，不获得录音、转写正文或重试权限。
- 不保存音频、标题、文件名、prompt、模型输出、API Key、完整 URL、上游错误正文或原始 HTTP header。用户身份通过当前账号关联获取，不复制邮箱快照。
- 记录最近 30 天，录音删除后元数据保留至到期。启用前历史不补造。调用记录不参与受理核对、重试、收费或资源清理裁决。
- 记录写入失败时不启动尚未发出的远端操作；结果记录失败不重发请求，保留中断/未知状态供查询。恢复与异常退出不能使记录伪装成成功或自动重放。

[查看个人及全站调用](use-case/inspect-calls.md) · [数据、权限与生命周期](architecture.md)
