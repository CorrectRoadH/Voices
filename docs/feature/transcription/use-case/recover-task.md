# 处理失败与恢复待核对任务

## 用户目标与起始状态

用户的录音处理失败，或数据库恢复后存在隔离任务，希望了解原因并选择允许的后续操作。

## 完整路径

1. 进入“处理任务”或录音详情，查看录音名称、真实阶段和具体原因。服务商受理结果不明的任务显示为“失败”，归入失败筛选；录音 ready 只表示音频已就绪。 {#inspect}
2. 对允许安全重试的失败任务选择“重试”。是否允许以服务端资源状态为准，不能仅因处于上传阶段隐藏安全重试；不确定远端创建请求不自动重发。 {#retry}
3. 受理结果不明时选择“重新转写”，进入新版本确认表单。表单提示可能重复收费；点击“开始转写”即确认新建，取消不发送请求。旧任务与远端操作仍保留供核对和清理。 {#new-version}
4. 数据库恢复造成的“恢复待核对”任务保留核对入口。用户可记录观察或确认该操作已有的远端 ID；未知 ID 由运维者核实后通过本机命令登记。恢复模式中仅允许查看，退出模式后才可提交核对。 {#reconcile}

## 结果与异常

| 情形 | 可观察结果 |
| --- | --- |
| 普通 uncertain 任务 | 不显示“结果待确认”或要求用户填写核对表，直接提供重新转写 |
| restore_hold 任务 | 保留恢复隔离；“暂未查到”不解除隔离，已知任务只查询原任务 |
| 恢复模式 | 禁止重试、新建和核对写入，退出恢复模式也不自动解除既有隔离 |
| 无详细历史原因 | 明确说明未记录，不能推测故障 |
| 录音已删除 | 名称显示不可用，不提供失效链接 |
| 状态刷新失败 | 保留已显示任务，提供重试入口 |

原因覆盖超时、取消、DNS、TLS、连接、响应读取、响应过大、JSON、资源 ID 缺失与本地登记失败。只展示受控代码及已知 HTTP 状态，不显示原始服务商正文、URL、凭据或音频。内部代码和任务 ID 在“任务详情”中查看。

验收核对失败筛选、按钮条件、确认与取消、恢复限制和旧任务保留；不能以新任务成功证明旧远端资源已清理。

## 直接请求隔离

OpenAI 已消耗发送许可或 error_code=direct_request_interrupted 时不允许同一任务重试；API 返回 409/direct_request_interrupted。Job API 的 duplicate_risk 将未成功且已消耗许可或恢复隔离的直接任务标记为收费风险，包含取消后的任务；明确确认新版本才允许新请求。OpenAI 不支持 remote ID 核对（409/direct_reconciliation_unsupported）。快照恢复隔离所有非成功直接任务，并为尚无任务的 OpenAI 自动转写意图建立失败版本；本地预处理可恢复，不自动发送转写。
