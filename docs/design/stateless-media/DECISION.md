# 无状态存储裁决

## Decision

Selected: [chunked](plans/chunked/README.md)

## Rationale

应用无状态，PostgreSQL 保存媒体、业务数据、会话与任务。多个 Go 副本不需要粘性路由或持久应用磁盘。
媒体采用 blobs 清单和 1 MiB bytea 块；短事务写入，完整内容与业务引用原子发布，读写租约保护跨请求生命周期。

采用数据库内音频存储后，备份只需覆盖 PostgreSQL 数据和独立保管的部署秘密。应用临时文件可重建。
深链接绑定录音、转写版本和片段 UUID，保留既有鉴权；文字编辑不换 ID，重转不改变旧链接的目标。

## Rejected Options

Large Objects 支持大对象和随机读取，但描述符受事务生命周期约束，OID 也需要独立清理协议。
本项目需要短事务、普通外键和可观察的分块回收，选择明确的块表模型；没有引入额外对象存储服务。

## Residual Risks

音频使数据库体积、WAL 和备份流量增长，实际容量与吞吐需在实现后验证；分块大小是设计初值，不是基准测试结果。
分块存储增加清单、租约和回收逻辑，必须验证跨块读取、上传中断、旧执行者及删除并发。

数据库回退不能证明远端请求未发送；恢复模式隔离可能重试的任务。人工“暂未查到”不构成远端终结证据。
以上规则避免盲目重复提交，但外部不确定状态仍可能需要人工核对；它不等于外部服务 exactly-once。

## Review conclusions

独立原生 Codex / GPT-6.1 Sol 审查覆盖发布、去重、租约、删除、备份恢复和深链接身份。
首次发现快照回退后重复收费风险，以及人工查询观察可能导致提前删除登记记录。
[架构](../../architecture.md) 已增加恢复隔离、终结证据和反例验收；限定复审通过，无剩余阻塞定案问题。

此裁决更新 [初始架构](../foundation/README.md) 的媒体持久化与实例边界。裁决形成时尚无产品代码；后续实现的运行时验收以测试与 Memory 记录为准。
