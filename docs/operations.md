# 运行与恢复

## 配置

| 变量 | 含义 |
| --- | --- |
| DATABASE_URL | PostgreSQL 连接串，必填 |
| ALLOWED_ORIGINS | 可选、逗号分隔的额外可信浏览器来源，只允许完整 http/https origin，不带路径或通配符；PUBLIC_BASE_URL 的来源始终允许 |
| PUBLIC_BASE_URL | 首次导入数据库的对外绝对 URL，默认 http://localhost:8080 |
| LISTEN_ADDR | 默认 127.0.0.1:8080；容器使用 0.0.0.0:8080 |
| SONIOX_API_KEY / ASSEMBLYAI_API_KEY | 首次导入数据库的 STT 凭据，读取 API 不返回原文 |
| LLM_BASE_URL / LLM_MODEL / LLM_API_KEY | 兼容既有直接启动方式的可选首启导入；新部署在管理员首次站点初始化页面填写并测试，Compose 不传入这些变量 |
| WEB_DIR | 编译后的前端目录，默认 web/dist |
| TEMP_DIR | 可丢弃临时目录；运行账户须可写 |
| MAX_UPLOAD_BYTES | 单文件上限，默认和最大值均为 2147483648 |
| TRANSCRIPTION_CONCURRENCY | 全实例有效租约上限，默认 2 |
| PREPARE_CONCURRENCY | 全实例音频准备并发，默认 1 |
| RESTORE_MODE | 数据库快照恢复首次启动设为 true |

数据库连接与三种服务商密钥支持同名 `_FILE` 变量。值为挂载 secret 文件路径；同一配置不得同时设置值与文件。
所有副本须使用一致配置。服务器不信任任意转发头，不使用请求 Host 生成句子链接。反向代理必须正确保留 Origin。浏览器来源须匹配 PUBLIC_BASE_URL 或显式 ALLOWED_ORIGINS；拒绝任意 Host 和转发头作为授权依据。

临时目录至少需容纳同时进行的上传原件、预处理输入及输出。Compose 为临时目录设置 6 GiB 限额，应用内存限制为 2 GiB；容量不足时任务失败，数据库原件保留。
上传无断点续传。连接中断后可使用同一导入选项整文件重传；服务器使用幂等键和内容摘要去重。


`.env` 文件不是必需。服务器可直接读取进程环境；若存在工作目录 `.env` 则读取它，同名进程环境变量优先。业务配置的优先级为数据库 > 环境（含 `.env`）：仅在 `server_settings` 没有配置行时导入。已有数据库配置不会被环境覆盖，空密钥也不会回退环境；旧业务环境值及旧密钥文件不会再次读取。

管理员在「服务器管理 → 服务器设置」修改站点、可信来源、STT 和 LLM 配置。保存写入数据库，LLM 对新任务立即生效，已接受的任务持有原配置直到终态清除。站点、可信来源和 STT 仍需重启全部应用副本后生效；页面显示的是当前实例与已保存配置的差异。普通用户的转写偏好仍独立保存。数据库连接、监听地址、目录、恢复模式、并发与上传上限继续使用部署环境。

凭据保存在数据库中，没有应用层加密；数据库角色、磁盘、备份和副本需按包含服务商凭据保护。API 只返回是否配置；修改审计只记录字段名。STT 密钥轮换应保持服务商账号不变；切换账号前先完成旧任务及远端资源清理。

修改站点域名或协议前需配置代理和 TLS。路径前缀改变还需使用相同的 `PUBLIC_BASE_URL` 路径重新构建前端并同步代理，然后重启全部副本。构建时没有数据库连接，构建参数不改变数据库中的业务配置。健康检查始终使用固定根路径 `/healthz`，不依赖站点前缀。

若配置错误导致无法登录，数据库运维者可在备份后以事务修复 `server_settings.value_json` 的 `public_base_url` 或 `allowed_origins`，同时递增 `revision` 并更新 `updated_at`，随后重启全部应用副本。不要删除整行或依赖 `.env` 覆盖，否则可能重新导入旧密钥。

## 启停与扩容

启动时在 PostgreSQL advisory lock 下执行有序迁移；失败不接受业务请求。多个应用副本共用数据库，会话和任务不依赖粘性路由。
退出时停止领取任务并取消在途请求；其他副本在租约过期后接管。旧执行者不能发布结果，但已发请求的晚到远端 ID 仍可登记供清理。

`GET /healthz` 检查数据库连通性，始终位于根路径，不随 PUBLIC_BASE_URL 路径前缀变化。应用日志只记录请求 ID 和错误类别，不记录音频、转写正文、会话 token 或服务商响应正文。

## 备份与恢复

使用一致性 pg_dump 或 PostgreSQL 物理备份，音频块与业务数据同时保存。单独备份部署参数与服务商 secrets；不备份应用临时目录。

恢复步骤：

1. 停止所有旧实例，阻止它们再次连接恢复后的数据库。
2. 恢复数据库，首次启动设置 RESTORE_MODE=true。
3. 核对录音数量、版本、人物及音频摘要。该模式不执行远端操作，只允许查看数据及登记核对结果。
4. 查看 restore_hold 任务，在服务商控制台核对上传和转写 ID。快照没有操作记录也不能证明请求没有发生。
5. 退出恢复模式并重启后，使用任务页登记已经核对的 ID。两类远端操作核对完毕后，仅查询原任务，不再次上传或提交。
6. 无法确认时保留隔离；如需新建转写，明确接受重复收费风险。旧任务仍保留。

恢复时，缺失的上传和提交意图会建立待核对记录；prepared 也转为不确定状态。
记录“暂未查到”只保存观察，不解除隔离。普通应用重启不执行数据库恢复隔离步骤。

## 删除与服务商限制

删除先将录音标为 deleting，立即停止新读取和结果发布。已有读取在下一批检查时终止；读租约释放或到期后才回收字节块。
已知远端资源独立清理。sent、uncertain 或 restore_hold 存在时保留墓碑，不宣称完全删除。

Soniox 提供文件与转写删除接口。AssemblyAI 的成功转写删除会同时删除关联上传音频；没有转写 ID 的独立上传不能通过单独 API 删除。
这类资源会保留 cleanup_unsupported 告警；不以保留期限自动到期作为已删除证据。依据：[AssemblyAI 删除接口](https://www.assemblyai.com/docs/pre-recorded-audio/api-reference/transcripts/delete)。

没有时间戳或说话人信息的结果仍可编辑。系统不编造时间戳、不跨录音自动认人、不自动切分长音频，也不在服务商之间自动切换。

## 账号初始化与恢复

首次成功注册者成为系统管理员，后续注册者为普通用户。初始开放注册，管理员可关闭；已启用账号共用实例的转写服务额度。账号数据互相隔离，管理员管理权限不授予他人录音的读取权限。

从共享密码版本升级时，账号迁移只接受空业务库，旧会话失效。非空业务库会拒绝迁移并保留数据，必须先制定显式数据归属迁移，不能把数据自动归给首个注册者。升级前停止旧实例并备份；该数据库升级不能只回退二进制。

忘记密码时，运维者在已加载 DATABASE_URL 的本机运行 `voices reset-password <email>`，从标准输入提供新密码。成功会撤销该用户全部会话，不更改角色或启停状态。不要将密码写入命令行参数或日志。

网页仅允许记录观察或确认该操作已登记的远端 ID。未知远端 ID 由运维者在服务商控制台核实账号与录音归属后，通过 `voices resolve-job <job-id> <operation-id> <remote-id>` 登记，核对说明从标准输入读取。运维命令保留原有隔离与清理约束，不自动解除其他未核实操作。

## 发布镜像与版本

正式镜像：`correctroad/voices:<X.Y.Z>`，提供 Linux amd64/arm64。首次发布前该镜像尚不存在；Docker Hub 仓库须配置为 public 以支持匿名拉取。源码构建仍可使用 `docker compose up -d --build`。

使用已发布镜像（先按本文配置数据库密码和站点 URL）：

```sh
# .env 中设置 VOICES_IMAGE=correctroad/voices:具体版本
# 升级前备份 PostgreSQL；固定版本便于追踪。
docker compose pull app
docker compose up -d --no-build
docker compose exec app voices version
```

预构建镜像前端基路径为 `/`。部署到 `/voices/` 等子路径时，继续从源码按 `PUBLIC_BASE_URL` 构建；已有数据库中的站点地址也须一致。数据库迁移在启动时运行，回滚镜像前必须核对迁移兼容性，必要时恢复升级前备份。

## 更新服务与公告

`UPDATE_URL` 未设置时使用 `https://voices.niceeval.com/`，显式设为空禁用更新和统计；修改后重启应用。`UPDATE_TELEMETRY` 默认 true，设为 false 只关闭统计。统计发送数据库持久化的随机安装 UUID、版本、Go/OS/架构；Worker 从 Cloudflare 获取国家。恢复模式禁发统计。录音、账号与转写数据不发送。接收方由 UPDATE_URL 决定。独立克隆数据库须重新生成 instance_identity.instance_id，不能复用任务租约 ID；详见 [统计方案](research/release-updates/telemetry.md)。管理员在服务器设置查看发布说明并手动检查；后台每 24 小时检查，手动检查至少间隔 60 秒。失败明确显示状态并保留上次成功结果。

Worker 的部署与公告维护见 [update-worker/README.md](../update-worker/README.md)。更新提示不会自动安装软件。


## 管理概览与日志

管理员从站点概览查看数据库快照、账号/任务计数、ready blob 字节与当前实例限制。数据库 up 不表示 worker、服务商或全集群健康；查询失败明确显示错误。

系统日志区分长期保留的管理审计与最近7天运行异常。可按类型、日期筛选，运行异常支持请求 ID。运行异常只有路由模板、错误码、请求/任务 ID，没有原始请求或服务商正文；高负载与数据库故障时可能丢弃，本实例丢弃数在概览显示。清理在恢复模式仍运行，物理删除可能滞后于可见窗口；需要堆栈时查看容器日志。

## LLM 摘要

LLM Base URL 包含兼容服务所需路径（例如 /v1），服务须支持 Chat Completions、JSON object response format 与 max_completion_tokens。地址和模型必填，本地无认证服务可留空 key；配置重启生效，SDK 不继承 OPENAI_*。所有账号共用实例服务额度。生成只发送用户所选转写版本的文本与片段锚点，不发送音频或人物档案。

每次最多输出4096 tokens、等待120秒；无自动重试或模型降级。一个有效运行任务覆盖全实例，lease180秒，过期仅失败。兼容服务不支持参数时显示失败，请调整服务配置后显式重新生成。模型名变化使旧 queued 请求失败；地址或凭据更换前先完成排队任务，避免 queued 使用新服务。

数据库快照恢复的 Restore 入口将所有 queued/running 摘要任务转为 interrupted，保留成功结果。退出恢复模式后不会自动重放这些生成请求；重新生成可能再次收费。普通服务重启继续 queued，运行中断只标失败。删除录音会回收摘要、输入快照与幂等键，已发出的远端推理可能完成但无法写回删除的录音。

## 首次站点初始化与升级

首个管理员注册仅创建账号，接下来在独立初始化页面填写 LLM 地址、密钥、模型并显式测试；测试发送固定示例，可能产生一次调用费用，不发送录音，也不自动重试。当前修订测试通过后完成初始化，或清空全部 LLM 配置并明确选择暂不启用。中途退出后管理员可继续，完成前暂停后续用户注册。模型列表不代表生成协议验证通过。

升级到站点初始化版本前应备份数据库并停止旧版本的全部实例，再执行迁移和启动新版本；不要滚动混用旧 worker。已有管理员的站点迁移为已完成，不影响既有账号。缺少配置快照的历史 queued/running 摘要任务标记 interrupted，不自动重放；用户可确认后重新生成。迁移增加了表字段，旧版本运行不具备新配置快照的清理与初始化约束，回退须停止新实例并恢复升级前备份。
