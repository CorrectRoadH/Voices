# Voices UI 设计规范

Voices 是录音阅读与整理工具。界面的主要内容是录音、文字和人物，操作应围绕这些对象展开。使用者应能迅速回答：这是哪份内容、现在是什么状态、下一步能做什么。

本文件指导 `web/` 的界面实现与评审。产品行为以 [Concord 功能契约](../docs/feature/README.md)为准；全站交互由[界面主题与交互](../docs/feature/appearance/README.md)约束。涉及数据、权限、计费或资源生命周期的改变，先更新对应契约，不能用视觉调整代替业务设计。

## 1. 内容优先，减少常驻说明

- 页面只保留一个主要标题，标题与导航使用相同名称，例如“转写偏好”。
- 列表先展示对象名称和状态，再展示时间、服务商等辅助信息。任务通过录音名称进入录音项目，不要求用户识别 UUID。
- 每个事实只表达一次。徽标已说明“已配置”，就不再加一段“当前实例已配置”；只有保存值与生效值不同才解释差异。
- 说明必须帮助当前操作：格式要求紧邻字段，失败原因紧邻失败内容，删除和替换的后果紧邻确认操作。
- 任务 ID、内部错误代码、协议细节、备份和部署知识放在可展开详情或文档中。运维日志中的 HTTP 状态、用量和错误原因属于该页面的主要内容，可以直接显示。
- 没有备注时留白，不在每张卡片重复“暂无备注”。空列表才使用完整空态。
- 删除冗余文案时保留标签、可访问名称、错误反馈和必要后果说明，不能用只在 hover 时出现的提示承载必读信息。

| 避免                                            | 采用                               |
| ----------------------------------------------- | ---------------------------------- |
| “不改变已接受任务的选项快照”                    | “用于新录音”                       |
| 配置徽标、配置解释和页脚重复说明                | 一个配置徽标，必要时解释差异       |
| 搜索无结果仍显示“暂无人物 / 新建人物”           | “没有匹配的人物 / 清除筛选”        |
| 同一张任务卡两次显示“已完成”，并显示“失败 0 次” | 一个状态徽标，失败次数大于零才展示 |
| 一整段说明如何获取模型列表                      | “获取 LLM 模型”按钮及实际结果      |

## 2. 信息层级与布局

- 阅读页的正文是视觉中心。桌面使用正文与右侧工具栏；目录、摘要、录音信息分为页签，版本与人物管理使用折叠区域。
- 设置页按任务组织卡片。服务器设置单栏排列站点、STT、LLM；不要把相关输入分散到横跨页面的多个位置。
- 用卡片区分独立任务，不给每句话、字段和状态再套一层卡片。只有实际内容才渲染说明区或页脚。
- 页面容器沿用 `src/index.css`：桌面最大宽度 1360px，默认水平留白 44px；窄屏按现有断点缩减。阅读页遵循其专用布局，不另造全局宽度。
- 采用 4px 基础间距。图标与标签通常 4–8px，字段及小组 12–16px，卡片或章节 20–24px。优先 `gap-*`，避免累积多层外边距。
- 主要操作使用实心按钮；次要操作使用 outline；辅助导航使用 link 或 ghost。一个操作组只突出一个主要动作，删除用 destructive。
- 长标题换行或在列表中截断并保留可访问的完整名称；长 ID 必须折行，不撑宽手机页面。

## 3. 颜色、文字与视觉风格

- 保持安静、紧凑的内容型界面：中性背景、蓝色强调、清晰边界。不要新增装饰渐变、宣传型大标题或无意义图标。
- 颜色唯一来源是 `src/index.css` 的语义变量：background、card、foreground、muted、primary、destructive、border、ring。业务组件不要硬编码色值或单独覆盖深色配色。
- 字体沿用 Geist Variable 与 Noto Sans SC；正文通常 14–16px，辅助文字 12–13px。正文与必要说明不能靠极低对比度隐藏。
- 圆角与阴影沿用 shadcn 的 token 和现有组件。用边界与留白区分层级，不给普通卡片添加强阴影。
- 状态不能只靠颜色表达，使用文字与必要图标。数字、时间和用量适合等宽数字；不为普通文字引入等宽字体。
- 浅色、深色、系统主题使用同一结构；遵守 `prefers-reduced-motion`，关闭非必要旋转和过渡。

## 4. 状态必须准确

| 场景                     | 显示方式                                             |
| ------------------------ | ---------------------------------------------------- |
| 首次读取                 | 共用 `Loading`，保留可读的状态文字                   |
| 已有内容刷新或轮询       | 保留内容；主动刷新在对应入口显示忙碌反馈             |
| 加载更多                 | 保留已有条目，只让“加载更多”显示 loading             |
| 切换筛选、对象或权限范围 | 清除不属于新范围的内容，旧响应不得覆盖新视图         |
| 真正没有内容             | 内容名称、简短下一步、必要的创建入口                 |
| 筛选无匹配               | 明确说“没有匹配”，提供清除筛选，不鼓励重复创建       |
| 请求失败                 | 停止 loading，保留草稿或已有结果，展示原因与重试入口 |
| 后台执行                 | 展示实际阶段，允许离开；不编造百分比                 |

- 转写 loading 覆盖 queued、uploading、submitting、polling、normalizing 及重试等待等真实阶段。音频 ready 只表示“音频已就绪”。
- 用户任务的内部 uncertain 显示为“失败”，失败筛选包括它；重新转写使用一次明确提交。底层远端操作、重复受理保护及恢复隔离保持独立。
- 调用日志属于诊断记录，允许保留“结果待确认”等精确调用结果；一次调用成功不表示任务已完成。不要为统一视觉而改写历史事实。
- 目录和摘要的提示必须对应当前页签，不能在摘要区域用“尚未生成目录”代替自身空态。

## 5. 操作、表单与反馈

- 点击后立即反馈。使用项目 `Button` 的 `loading` 属性，它封装了 Spinner、`aria-busy` 和禁用行为；不要使用不存在的 `isLoading`。
- 同页多个动作使用 `useAction.pendingKey` 精确定位。正在变更角色时只有该按钮转动，其它互斥操作禁用；普通禁用不等于执行中。
- Switch 只表达持续的开关状态。用于即时保存时，在控件附近显示保存中，失败恢复原值。不要把确认流程包装成一个额外收费开关。
- 重试保留原参数，已有一次确认足够。新建独立转写版本的提交按钮就是确认；删除、密码修改后退出、覆盖既有结果等后果须在动作附近说明。
- 设置使用其既有保存模式，不在同一表单混用自动保存和手动保存。自动保存用一个状态行表达，不重复堆放解释。
- 单字段编辑复用 `InlineEdit`。单行 Enter、多行 Ctrl/⌘+Enter 保存，Escape 取消，IME 组合期间不提交；失败保留草稿，无变化不发请求。
- 主动操作失败显示 toast，并在相关区域保留原因；后台轮询失败不反复弹 toast。取消或废弃请求不报错。
- 凭据不回显，留空保留、显式清除。降低视觉噪声不改变权限、恢复模式或秘密保护。

## 6. 组件与可访问性

技术栈固定为 React、Tailwind v4、shadcn/ui Base UI（base-nova）和 Lucide。优先使用仓库已有组件，不为相同功能新增第二套样式。

| 用途                       | 组件或入口                                                     |
| -------------------------- | -------------------------------------------------------------- |
| 页面标题、空态、错误、加载 | `PageHeading`、`EmptyState`、`ErrorBox`、`Loading`             |
| 表单                       | `FieldGroup`、`Field`、`FieldLabel`、必要的 `FieldDescription` |
| 状态                       | `Status`、`Badge`；运行状态配 Spinner                          |
| 局部编辑                   | `InlineEdit` 及现有业务编辑器                                  |
| 对话框                     | `Modal` / Base UI Dialog，必须有可访问标题                     |
| 低频诊断                   | 原生 `details` / `summary`，键盘可展开                         |
| 对象导航                   | React Router `Link`；按钮渲染链接使用 Base UI `render`         |

- 卡片使用 Header / Title / Content，Description 和 Footer 仅在有内容时出现。
- 交互控件必须有可访问名称；图标按钮不能只依赖 tooltip。输入用关联 label，错误用 `aria-invalid`，异步状态用 `role="status"` 或 `aria-busy`。
- 保留键盘焦点环，弹窗关闭回到触发点；触摸设备不能依赖 hover 才能完成操作。
- 聊天正文轻点用于阅读，编辑从消息菜单进入。多选以气泡外统一左侧勾选和整行高亮表达，固定工具栏承载批量操作；手机工具栏位于播放器上方。复制失败与手动复制窗口关闭均保留选择。
- 图标采用 Lucide；按钮内图标用 `data-icon`。不要为浮层手工抬高 z-index。
- 中文和英文一起维护，完整句子通过 `tr` 翻译；不要依赖中文短文本宽度定位控件。

## 7. 响应式与验收

- 在约 375px 手机宽度和桌面宽度检查，无水平溢出；长标题、错误、英文和大字号不遮挡主要操作。
- 手机的固定播放器必须为正文与浮层预留空间，底部操作可触达；桌面阅读区与侧栏按既有规则独立滚动。
- 核验正常、空态、筛选无结果、加载、提交、失败和恢复，而不只看静态成功截图。
- 对异步操作用确定性的网络延迟验证即时 loading、阻止重复提交、成功收敛和失败可恢复。fake 只替代外部边界，不复制核心实现。
- 文案和布局小改不新增只检查字符串的测试；影响操作和状态的改动通过正式入口验证，并检查相关截图。
- 使用 `vp run check`（隔离 `TEST_DATABASE_URL`）、相关浏览器脚本以及 `concord check`。测试通过不代表已部署；交付注明实际验证范围。

新增页面或修改现有 UI 前先读本文件。若规范与业务契约冲突，先核对具体行为并更新唯一 owner，不复制出另一套业务规则。
